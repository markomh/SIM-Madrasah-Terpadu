# Human Workflow & Decision Audit Prompt

**Domain:** Indonesian Education ERP / SIM Madrasah / School Information System
**Role:** Senior UX Researcher, Human Factors Specialist, Cognitive Psychologist, Enterprise Product Designer, Education ERP Consultant, Information Architect

---

# Objective

Do NOT evaluate visual design first.

Do NOT evaluate CSS first.

Do NOT evaluate frontend components first.

Instead, evaluate whether the dashboard supports how Indonesian educators actually think, make decisions, and complete their daily work.

The objective is to measure **Human Workflow Quality**, **Decision Support Quality**, and **Operational Efficiency**, not merely UI quality.

Assume the users are:

* Guru Mata Pelajaran
* Guru Kelas
* Wali Kelas
* Guru BK
* Pembina Ekstrakurikuler
* Kepala Madrasah
* Tata Usaha
* Operator Madrasah
* Orang Tua

Always evaluate the dashboard from the user's perspective, not from the database structure or application modules.

---

# PART 1 — Daily Workflow Audit

For every role:

Analyze the complete daily workflow.

Morning

Teaching

Administration

Assessment

Communication

End of Day

For every stage identify:

* Primary Goal
* User Questions
* Required Information
* Required Actions
* Required Decisions
* Current Dashboard Support
* Missing Information
* Missing Actions
* Workflow Friction
* Estimated Time Lost
* Improvement Recommendation

---

# PART 2 — Decision Support Audit

For every role evaluate:

Does the dashboard help users answer:

What should I do now?

What is most urgent?

What requires my attention?

What has changed?

What requires approval?

What is overdue?

What is blocking my work?

What can wait?

For every decision evaluate:

* Required Information
* Current Information
* Missing Context
* Decision Confidence
* Decision Speed
* Improvement Recommendation

---

# PART 3 — Attention Priority Audit

Evaluate whether visual attention follows operational priority.

Determine:

What users notice first.

What users should notice first.

Identify:

* High Priority Information
* Medium Priority Information
* Low Priority Information
* Noise
* Redundant Widgets
* Distracting Components

Recommend a new priority order based on actual daily work.

Good

Critical

* Number of simultaneous decisions
* Number of competing actions
* Number of visible KPIs
* Number of icons
* Number of colors
* Number of alerts
* Reading complexity
* Information overload
* Visual noise

Identify:

* Unnecessary information
* Duplicate information
* Hidden important information

Estimate overall cognitive load.

Identify:

First Fixation

Second Fixation

Third Fixation

Visual Flow

Eye Path

Dead Zones

Attention Traps

Visual Competition

# PART 7 — Information Value Audit

Evaluate every dashboard element.

For every card ask:

If this card disappeared,

would the user's daily work become harder?

Classify:

Critical

Important

Helpful

Optional

Redundant

Recommend removing low-value information.

Teaching

Assessment

Administration

Communication

Reports

Analytics

# PART 9 — Mental Model Audit

Determine whether the dashboard follows:

A.

Database Structure

or

B.

Teacher Mental Model

Identify every place where the UI reflects internal system architecture instead of real-world teacher workflows.

Recommend restructuring according to user mental models.

# PART 10 — Zero Training Audit

Assume:

A teacher aged 50+

Minimal digital literacy

First day using the system

No documentation

No training

Evaluate:

Can the teacher complete:

Attendance

Journal

Grades

Permissions

Communication

Reports

without assistance?

Identify every usability barrier.

---

# PART 11 — Classroom Reality Audit

Evaluate real classroom conditions.

Assume:

Students are waiting.

Internet may be unstable.

Teacher has less than one minute.

Teacher uses one hand.

Teacher is standing.

Teacher is under time pressure.

Determine whether the dashboard still supports efficient operation.

---

# PART 12 — Emergency Scenario Audit

Evaluate scenarios such as:

Internet disconnected

Server slow

Power interruption

Unexpected browser refresh

Large class sizes

Multiple simultaneous notifications

Determine whether users can continue working safely without losing progress.

# PART 14 — Improvement Roadmap

Prioritize findings into:

Immediate Fixes (less than 2 hours)

Quick Wins (less than 1 day)

Short-term Improvements (1–2 weeks)

Medium-term Improvements (1–2 months)

Long-term UX Evolution

Rank every recommendation by:

* User Impact
* Business Impact
* Educational Impact
* Technical Complexity
* Development Cost
* Implementation Priority

---

# Rules

* Evaluate real operational workflows instead of UI aesthetics alone.
* Prioritize teacher productivity over visual appearance.
* Base recommendations on Indonesian school and madrasah operational contexts.
* Focus on reducing cognitive load, minimizing clicks, improving decision-making, and accelerating daily tasks.
* Support every finding with clear evidence, measurable reasoning, and expected user impact.
